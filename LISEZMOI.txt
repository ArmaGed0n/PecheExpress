PÊCHE EXPRESS — MISE EN LIGNE (SITE STATIQUE) + CLASSEMENT SUPABASE
=====================================================================
VERSION 1.0.15

Le jeu est un site statique (HTML / CSS / JS) hébergé sur GITHUB PAGES. Le classement en ligne utilise SUPABASE
(base de données + Edge Function). Supabase ne sert pas de sites web (ses pages HTML sont renvoyées en texte brut) : c'est pour ça
que les fichiers du jeu sont sur GitHub Pages.

1) METTRE LE SITE EN LIGNE SUR GITHUB PAGES
   a) Crée un compte sur https://github.com puis un nouveau dépôt PUBLIC (ex. « peche-express »). GitHub Pages gratuit exige un dépôt public.
   b) Dépôt > « Add file » > « Upload files » : glisse TOUT le contenu du dossier (index.html, sw.js, manifest.webmanifest, .nojekyll,
      css/, js/, icons/, db/, supabase/, LISEZMOI.txt...) puis « Commit changes ».
      (Si .nojekyll n'apparaît pas, c'est normal : les fichiers cachés sont parfois ignorés. Ce n'est pas bloquant pour ce jeu.)
   c) Dépôt > Settings > Pages > « Build and deployment » : Source = « Deploy from a branch », Branch = main, dossier = / (root) > Save.
   d) Après 1 à 2 minutes, le jeu est disponible à :  https://<ton-pseudo-github>.github.io/<nom-du-depot>/
      C'est le lien à partager. Les adresses sont relatives : ça marche dans un sous-dossier.
   e) Pour une mise à jour : dépôt > « Add file » > « Upload files », glisse les fichiers modifiés (ils remplacent les anciens) > Commit.
      Compte ~1 à 2 minutes avant que ce soit en ligne. Ne mets JAMAIS de clé secrète Supabase dans le dépôt (il est public) : ce projet n'en contient aucune.
   Remarque : GitHub Pages n'accepte pas de fichier d'en-têtes. La politique de sécurité (CSP) est donc dans une balise <meta> de index.html.

2) INSTALLER SUR LE TÉLÉPHONE
   - iPhone (Safari) : Partager > « Sur l'écran d'accueil ». Android (Chrome) : menu ⋮ > « Installer l'application ».

3) CONFIGURER LE CLASSEMENT SUR SUPABASE (une seule fois)
   A. Crée un projet sur https://supabase.com (gratuit). Note le « Project ref » (dans l'URL du tableau de bord, ou Project Settings > General).
   B. Base de données : Supabase > SQL Editor > New query > colle TOUT le fichier db/schema.sql > Run.
      (Il crée les tables ET active la protection RLS : la clé publique de Supabase ne peut pas lire les identifiants privés des joueurs.)
   C. Fonction serveur (avec la CLI Supabase, depuis le dossier du projet) :
        npx supabase login
        npx supabase link --project-ref <ton-project-ref>
        npx supabase functions deploy leaderboard --no-verify-jwt
      Sans CLI : Supabase > Edge Functions > Deploy a new function > nom « leaderboard » > colle supabase/functions/leaderboard/index.ts >
      Deploy, puis dans les réglages de la fonction DÉSACTIVE « Verify JWT » (les joueurs n'ont pas de compte Supabase).
   D. (Recommandé) Limite l'accès à ton site :  npx supabase secrets set ALLOWED_ORIGINS=https://<ton-pseudo-github>.github.io
      (seulement le domaine, SANS /nom-du-depot ; plusieurs adresses possibles, séparées par des virgules). Sans ce secret, la fonction accepte tous les sites.
   E. Ouvre js/config.js et remplace la valeur par l'adresse de ta fonction :
        window.PECHE_EXPRESS_API = "https://<ton-project-ref>.supabase.co/functions/v1/leaderboard";
      Puis republie le site (numéro de version + changelog comme en 4).
   F. Test : ouvre https://<ton-project-ref>.supabase.co/functions/v1/leaderboard?category=level&period=all dans le navigateur :
      tu dois voir {"category":"level","period":"all","rows":[]}.
   La base se connecte toute seule à la fonction (variable SUPABASE_DB_URL fournie par Supabase) : aucune clé à recopier.

3 bis) REPRENDRE LES DONNÉES DE L'ANCIEN CLASSEMENT NEON (si tu en as)
   Les joueurs gardent leur identifiant : ils retrouvent leur place sans rien faire.
   1. Récupère l'URL de connexion Neon (NEON_URL) et celle de Supabase (Project Settings > Database > Connection string : SUPABASE_DB_URL).
   2. Dans un terminal avec PostgreSQL installé (pg_dump et psql) :
        pg_dump --data-only --column-inserts -t leaderboard_players -t leaderboard_weekly "$NEON_URL" > donnees.sql
        psql "$SUPABASE_DB_URL" -f donnees.sql
      (Fais-le APRÈS avoir exécuté db/schema.sql sur Supabase. Si tes tables Neon datent d'avant la 1.0.9, exécute d'abord sur Neon :
       ALTER TABLE leaderboard_players ADD COLUMN IF NOT EXISTS public_id UUID NOT NULL DEFAULT gen_random_uuid();
       ALTER TABLE leaderboard_players ADD COLUMN IF NOT EXISTS profile JSONB NOT NULL DEFAULT '{}'::jsonb;
       ALTER TABLE leaderboard_players ADD COLUMN IF NOT EXISTS profile_updated_at TIMESTAMPTZ;)
   3. Une fois que tout marche, tu peux supprimer la base Neon et la variable DATABASE_URL de Netlify.

4) FAIRE UNE MISE À JOUR DU JEU
   a) Modifie les fichiers du jeu.
   b) Dans sw.js change le numéro : const VERSION = "1.0.14";  (nouveau numéro à chaque fois). Mets le MÊME numéro dans js/game.js
      (APP_VERSION) et dans index.html (balise app-version).
   c) Dans changelog.json AJOUTE EN HAUT une entrée (version, date, notes). Elle s'affiche dans « Nouvelle version disponible »
      et dans « Nouveautés ».
   d) Envoie les fichiers modifiés sur GitHub (étape 1e). Chez tes amis, un bandeau propose la mise à jour ; leur progression est conservée sur leur téléphone.

5) STRUCTURE DU PROJET
   - index.html (avec la politique de sécurité CSP), css/style.css, js/*.js : le jeu (sprites.js = textures, game.js = logique,
     leaderboard.js = classement, config.js = adresse Supabase, changelog.js / pwa.js = mises à jour), sw.js = cache hors connexion.
   - supabase/functions/leaderboard/index.ts : l'API du classement (Edge Function, Deno).  supabase/config.toml : réglage de la fonction.
   - db/schema.sql : tables du classement + protection RLS (à exécuter dans le SQL Editor de Supabase).

SÉCURITÉ
   - La sauvegarde du jeu est locale à l'appareil : ce n'est pas un système anti-triche (niveau et XP sont envoyés par le jeu).
   - Identifiant privé (playerId, sur l'appareil) : il n'est jamais affiché ni renvoyé. Les joueurs sont montrés avec un identifiant public aléatoire.
   - Les tables sont en RLS sans règle : l'API de données Supabase (clé anon) ne peut ni lire ni écrire dedans. Seule la fonction y accède.
   - Le serveur n'accepte que des valeurs d'une liste fixe (cadre, avatar, bannière, titre, badge, poisson) et nettoie le pseudo.
   - Limites : 1 prise toutes les 3 s et 1 modification de profil toutes les 2 s par joueur. Pas de filtre de mots interdits sur les pseudos :
     pour modérer, dans le SQL Editor :  UPDATE leaderboard_players SET pseudo = 'Pêcheur' WHERE pseudo = '...';
   - La fonction est publique : si tu constates des abus, active ALLOWED_ORIGINS (étape 3D) et surveille Edge Functions > Logs.

CHANGER D'ADRESSE DU JEU (ex. de Netlify vers GitHub Pages) SANS PERDRE LA PROGRESSION
   La progression est stockée dans le navigateur, PAR ADRESSE : une nouvelle adresse = une partie vierge, sauf transfert.
   1. Publie d'abord la version 1.0.13 (ou plus) SUR L'ANCIENNE ADRESSE : elle ajoute le transfert de sauvegarde.
   2. Chaque joueur ouvre l'ancien lien, accepte la mise à jour, puis Profil > Réglages > « Exporter ma sauvegarde »
      (un fichier est téléchargé et le code est copié).
   3. Il ouvre le NOUVEAU lien, Profil > Réglages > « Importer une sauvegarde » : choisit le fichier (ou colle le code) > Importer.
      La progression, le pseudo et l'identité du classement sont repris.
   Cela sert aussi à changer de téléphone. L'import remplace la progression de l'appareil (une copie de secours de l'ancienne est gardée).
